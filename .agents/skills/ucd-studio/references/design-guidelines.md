# 默认设计规范与模板定制

只有在定制视觉系统、密度或手工扩展组件时读取。普通 init / patch 会直接应用这些约定并同步生成 design-system.md，无需先加载本文件或其他设计技能。

## 设计方向与优先级

面向每天处理审批、查询与协作的内部业务人员，采用 Operate 模式：主任务清楚、数据便于扫描、操作符合熟悉的业务界面。用户指定的产品规范、业务字段及既有品牌优先；缺少规范时才使用本包默认值。不要把精致理解为装饰，不用营销首屏、装饰眉题、全大写标签、光晕、重复卡片或无依据的趋势来填满页面；业务内容不使用渐变，渐变仅保留于侧栏品牌标识方块、聚焦光环与顶栏品牌发丝线，按钮一律实色。

默认 palette（第四轮"霁蓝瓷面"）：霁蓝 `#1f4fd8`、冷调瓷白工作区 `#f4f6f9`（带蓝灰倾向）、内容面 `#ffffff`、深岩蓝黑正文 `#101c2c`、蓝灰辅助文字 `#55637a`；中性阶一律带蓝灰色相，不用纯灰。蓝色用于主操作、焦点与当前选择；成功、警告和错误有独立文字与背景 token，不能只靠颜色传意。浅色用于常规明亮办公环境；midnight 是显式可选主题，不按设备偏好擅自切换。主题及页面 tokens 合并后的值才是规范依据。

每主题另含六个结构性 token：`surface-2`（凹陷面：侧栏轨道、表头、看板井区、骨架底、分段控件槽）、`line-strong`（控件 hover 描边）、`shadow`（面板与卡片两层弥散阴影：`0 1px 2px` + `0 16px 40px -16px`，透明度 ≤12%，色相随主题 ink）、`shadow-pop`（dialog、toast 等浮层阴影，加深至 ≤.22）、`ring`（聚焦光环，primary 的透明化）、`scheme`（light/dark，驱动原生控件 color-scheme）。高度二选一：面板、卡片与浮层只用阴影不描边；输入、行分隔与 details 等平面元素只用 1px `border` 描边不加阴影。面板 radius 默认 14px，控件圆角 10px（`--control-radius`），徽标、导航项、chip 与 tabs 为 pill（`--r-pill`）。顶栏为 sticky 磨砂玻璃（blur + saturate + 半透明底）+ 底部 2px 品牌渐变发丝线，磨砂仅限顶栏与窄屏抽屉；面板与卡片保持实色。

## 排版与尺寸

系统字体 Segoe UI / PingFang SC / Microsoft YaHei / system-ui，字体资源不联网。页面标题 21px/650（窄屏不再单独缩小）；区块标题 15px、次级标题 14px；正文 14px/1.65、数据与控件 13px、辅助文字至少 12px。标题和字段左对齐，层级靠字重与灰度而非大跨度字号；数字使用等宽数字特性；说明文字建议约 65–75ch，数据表不强制套用正文行长。

间距以 4px 为基准，优先使用 8 / 12 / 16 / 20 / 24 / 28px；同一组内容靠近，不同任务组适当分隔。密度不缩小文字：

| 规则 | compact | comfortable |
|---|---|---|
| 表格单元格内边距 | 10px 16px | 12px 24px |
| 面板头内边距 | 12px 16px | 20px 24px |
| 面板内容内边距 | 16px | 24px |
| 桌面常规控件最小高度 | 36px | 36px |
| 桌面小按钮最小高度 | 30px | 30px |
| 窄屏主要交互目标最小高度 | 44px | 44px |

内置布局明确使用 compact；自行编写完整配置时省略 density 则为 comfortable。面板圆角使用主题 radius（默认 14px），控件沿用统一外形，禁止逐个添加不同阴影或圆角。

上表内边距为桌面规则。760px 及以下两种密度的面板统一为头部 14px 16px、内容 16px；表格仍保留所选密度内边距，在局部容器内滚动。

## 结构与六类模板

公共骨架为 224px 凹陷侧栏、52px 最小磨砂顶栏和 12 列内容网格。1180px 及以下侧栏收紧至 200px；760px 及以下侧栏变为横向 pill 区块导航、顶栏最小 48px、全部区块单列。侧栏导航项为 pill 态（active 浮起 surface + 微阴影），导航是真实本页锚点，不伪装成尚未实现的业务路由。页面标题直接说明任务，旧 eyebrow 字段可读入但不展示。

| 布局 | 主任务与默认结构 |
|---|---|
| admin | 查询和筛选记录；筛选栏、结果与分页在同一数据区，汇总不抢占主表格 |
| dashboard | 从待办了解工作；汇总和趋势服务于后续操作，不添加无数据依据的图形 |
| workbench | 工具入口 / 主队列 / 动态采用 3/6/3 列；其他常规区块 4 列，full 跨 12 列 |
| form | 主表单 / 属性说明 8/4 列；中屏 7/5 列，窄屏字段单列 |
| detail | 属性、页签与处理时间线职责分开，使用稳定字段顺序 |
| kanban | 阶段标题与数量清晰，任务用 select 移动；窄屏阶段纵向排列 |

默认区块为 6 列；workbench 与 form 的组件专属规则优先，span=full 始终跨 12 列。中屏 workbench 的工具、表格和动态改为 6 列，末尾动态跨 12 列。看板有自己的阶段网格，不借用外部页面列数。

表格在自身容器局部滚动，保持数据字号；长名称、说明、操作组允许重排。不要用全页 overflow:hidden 掩盖问题，也不要在窄屏隐藏必需字段。

## 组件与状态约定

- 共用操作名称、形状和状态色；主操作突出，次操作安静。内置图标使用统一线条的本地 SVG，不用 emoji 或 Unicode 字符代替图标系统。
- hover / active 表达可操作性，focus-visible 在键盘导航时可见；disabled 只用于当前不可执行的操作。原生输入保留标签、必填标记、说明关联及校验能力。
- 表格提供搜索、状态筛选、排序、分页；无匹配可清除筛选。异常预览提供加载骨架、空、错误和就近恢复动作，恢复仅重置本地示例，不发请求。
- 表单先显示具体校验问题，再反馈本地校验结果；不能把校验通过说成真实提交成功。独立入口和空状态按钮仅提示本地操作，不假装已创建业务数据。
- 原生 dialog 用于示例草稿这类需要集中输入的动作，Esc / 取消关闭并恢复焦点；补充说明优先就近展示，不为普通说明新建弹窗。
- Tabs 支持方向键、Home / End；看板移动后更新数量。步骤条只是进度指示，不能承诺未实现的多步流程。
- 扩展异步组件时补 loading / empty / error / success 与恢复方式；静态区块无需虚构异步过程。权限或角色行为必须来自真实资料，不从示例推定。
- 不做页面入场动画；状态变化使用短过渡，尊重 prefers-reduced-motion。

## 规范生成与验证边界

design-system.md 由实际 page.json、选定主题、页面 token 覆盖及输出模式生成，包含来源、有效值、当前密度、区块跨度和已配置交互；不应列出页面中不存在的表单、看板或页签行为。定制运行时后应复查这些说明，特别是 editable 模式保留的 page.js。

普通正文和占位文字目标至少 4.5:1，大号文字至少 3:1；交互边界与焦点标记需检查至少 3:1。生成器给出部分实色组合的 WCAG 对比度，但不测透明度、所有交互状态或辅助技术表现；自定义颜色不会自动被修正，也不据此阻断生成。

浏览器复查主任务、焦点顺序、桌面/中屏/窄屏、长内容及加载/空/错误恢复。对比度计算、结构检查和 CSP 均不能替代实际渲染与宿主隔离验证。所有示例只在当前页面模拟，刷新后恢复，无真实后端、权限或持久化。
