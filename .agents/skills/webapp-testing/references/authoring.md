# 项目上下文与用例生成

## 现状目录

`analyze` 是静态证据收集器，默认最多扫描 5000 个候选文件，跳过依赖、构建、隐藏目录；单文件读取上限 128 KB，实体/接口/UI 线索有条数上限。它不会自动理解业务，不分析任意运行配置，不复制全量源码。

```text
python SKILL_DIR/scripts/webtest.py analyze --project APP --output APP/docs/testing-context
python SKILL_DIR/scripts/webtest.py analyze --project APP --output APP/docs/testing-context --requirements feature.md --staged
```

输出包括 `index.md`、`business.md`、`entities.md`、`stack.md`、`changes.md` 和精简 `evidence.json`。脚本会覆写这些生成文件；保留人工笔记时用独立文件或单独输出目录。分析目录推荐控制在几页文档规模，只维护被测业务相关事实。

agent 继续读取证据指向的源码并填写：

- 业务：角色与权限、主流程、状态机、输入/输出、失败与幂等规则；每条约束附路径/符号。
- 实体：核心类、表、主外键、状态枚举、关系、逻辑删除/租户约束；不复制全部字段。
- 栈与运行：Java/Spring Boot/Vue/Node 版本、模块、启动 profile/命令、API 路径、代理、token 位置、数据库种类和环境变量名。
- 影响范围：需求/暂存区变更关联接口、页面、实体、数据库迁移和可观察结果，明确未确认部分。

暂存区收集使用 `git diff --cached`，不混入未暂存改动。命名/注解只是线索，不能单凭 Controller 上的注解推断完整 URL，也不能单凭字段名推断唯一性或关联关系。Git diff 与需求做尽力脱敏，但用户自定义秘密命名可能漏检；本地审查后再共享。

## 从需求、现有用例或暂存区生成

先把输入逐条映射到用例 ID，保留来源（需求编号/用例编号/变更路径）。典型映射：

| 输入信息 | 要补充的验证 |
|---|---|
| 新建/变更业务状态 | 经真实接口构造前置 → 操作 → 详情/列表查询 → 持久化结果 |
| 增加约束或权限 | 合法、空值/边界、无权/过期 token、重复请求、失败后无副作用 |
| Vue 表单/按钮 | 唯一 ID、输入绑定、提交、加载/失败反馈、列表/详情更新 |
| Mapper/实体/迁移变更 | 表字段/默认值、唯一性、逻辑删除、租户、事务回滚与兼容影响 |

具体断言必须来自需求或实现证据，未知时列待确认，不能猜测业务码。后端常见组合是“创建依赖对象 → 新建业务对象 → 提交/审核 → 查询详情和列表 → SQL 检查状态/关联行 → 定向清理”。capture 提取前序真实响应 ID，避免写死现存生产数据。

测试数据优先用业务接口创建；接口无法构造的边界场景可用 SQL 预处理，说明为何需要。写 SQL 时用命名参数，精确标记/主键限定范围。尽量设计独立用例；同一用例内依赖步骤前序失败后会跳过，跨用例的共享变量仅用于明确的公共前置。

对于暂存区中的鉴权、页面 ID 变更，不能把变更本身当作授权：关闭鉴权与补 ID 仍按用户本会话已有授权处理。skill 不自动改目标项目源码或执行未确认的 SQL。

## 输出和复核

从 `init` 生成完整示例后，删除与本功能无关的数据库/浏览器步骤，替换接口、预期业务码、DOM ID、SQL、服务路径。示例是文档，不是可直接用于任意项目的已验证用例。

用例目录至少包含 `suite.json` 与可选 `sql/`。复杂说明可另写 `coverage.md`：需求→用例→接口/页面→DB 断言→执行状态，保留未覆盖原因。导出得到独立 `run.py` 与执行模块，其他人传前端地址与 token 即可复现；数据库连接环境变量和 Lightpanda 作为运行环境前提。

执行后根据 JSON/Markdown 报告区分断言失败、依赖/配置错误和跳过。未启动服务、未连接 DB 或浏览器受阻的部分必须明确，不以静态检查代替功能通过。
