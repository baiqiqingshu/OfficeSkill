QUICK START

声明式路由接入示例（5 分钟上线）

route-order-service.yaml
yaml
# 提交至内网 gitops-gateway 仓库即可自动校验并发布
apiVersion: gateway.internal/v1
kind: HttpRoute
metadata:
  name: order-core-api
  namespace: biz-trade
spec:
  hosts: ["order.internal.corp"]
  paths: ["/api/v2/orders"]
  upstream:
    service: order-service.biz-trade.svc
    timeoutMs: 3000
    canary: { weight: 10, target: "order-service-v2" }
  plugins:
    iamAuth: { enabled: true, requiredRole: "trade.reader" }
    rateLimit: { qps: 2000, burst: 400 }
1
统一内网域名
所有业务统一挂载 *.internal.corp，证书由内网 CA 自动签发续期。
2
灰度与限流声明化
无需改动业务代码即可完成 10% 灰度放量与 2000 QPS 保护。
08
BEST PRACTICES

生产上线最佳实践与避坑指南

推荐实践

推荐做法

  • 所有写接口须显式配置合理 timeoutMs（建议 2~5s），避免慢请求拖垮工作线程
  • 核心链路变更先走 5% 灰度观察 10 分钟，确认错误率与 P99 稳定后再全量
  • 在控制台为高价值接口配置独立的限流策略与告警接收组
注意风险

常见风险与禁区

  • 严禁对非幂等 POST / 支付扣款接口开启自动重试（retry），防止重复执行
  • 大文件上传/下载（> 20MB）禁止穿透网关缓冲，应走内网对象存储直传通道
  • 禁止在路由正则中编写高回溯表达式，发布前须通过 CI 静态校验
