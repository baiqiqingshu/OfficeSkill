# Native PPT 实施文档

## 目标与范围

将 `.agents/skills/intranet-ppt` 升级为 `native-ppt`（原生可编辑 PPT），保留旧命令路径兼容入口。以现有 Python 源码、JSON Schema 和组件库为实施依据，不读取既有 docs 文档。

本次覆盖六项需求：所有 PPTX 输出执行布局检查；普通文字默认黑色，保留标题及关键词显式强调；支持读取和配置母版标题、页脚高度并检查正文安全区域；优化技能名称；使用 PowerPoint 原生项目符号和编号；扩展可编辑、美观的元素库。

## 实施方案

1. 把技能主体迁移至 `.agents/skills/native-ppt`，旧目录保留兼容说明及 CLI 转发。内部 Python 包名暂保留，避免破坏已有导入。
2. 统一布局检查入口，覆盖 render、starter 和 extract 等会产生 PPTX 的命令，在输出报告中记录检查结果。render 保留诊断预览与问题明细；提供严格检查选项，问题未解决时不视为通过。
3. 增加母版区域读取和配置。标题/页脚区域使用像素高度，支持页面覆盖；正文检测有效内容边界，标题和页脚元素可声明所属区域，封面装饰可显式声明全页。增加 inspect-master 命令查看读取结果。
4. 将普通正文及缺省文本颜色设为 `#000000`；组件标题、强调、状态和深色背景上的对比文字仍可显式设置颜色。统一 PPTX、HTML 预览与布局估算的列表语义，项目符号写入 DrawingML 段落属性，不再把符号拼进正文。
5. 扩充内置库、示例输入与可视化目录，优先提供信息卡、流程、对比、计划和结论类组件，维持离线、原生可编辑的实现。

## 并行分工

- 布局与母版代理：CLI、母版区域模块、统一检查模块、Schema、区域使用说明。
- 文本与列表代理：组件编译器、PPTX 后端、主题、原生项目符号及黑色默认文字。
- 元素库代理：组件库、样例、演示页生成器、SKILL.md、名称兼容入口和相关说明。
- 主代理：方案、接口协调、实施文档、集成审查和最终提交。
- 独立验证代理：运行代表性生成命令及边界场景，检查报告和 PPTX 原生结构，不新增测试代码。

## 验收

在 `temp/` 生成验证产物，不提交临时输出或测试代码。验证普通文字黑色、局部强调保留、原生列表 XML、多级缩进、母版区域读取/覆盖、越界问题报告、各 PPTX 输出路径和旧 CLI 兼容。更新预生成元素库演示。完成后补充实际结果并自动提交相关改动。

## 实施结果

六项需求已落地，技能主体为 `.agents/skills/native-ppt`，原 `.agents/skills/intranet-ppt/SKILL.md` 和 CLI 路径保留转发兼容。Python 包名及已有输出目录标记保持兼容。

### 布局检查

`render`、`starter`、`extract` 均检查保存后的 PPTX，报告通过 `nativeChecks` 按文件名索引。`render` 另外检查编译场景的文字/表格溢出、元素重叠、页面边界与母版保留区；报告包含 `checked`、`status`、`issueCount`、`issues`。`--strict-layout` 在发现问题时退出 2，同时保留诊断产物；不加参数仍执行检查。SKILL 要求修正问题后再交付，不能把带问题的产物称为通过。

原生检查区分母版固定内容与新增组件，并将同一组件内部形状归组。固定文字、图片、表格包含新增内容时仍检查遮挡，真正的背景矩形可作为容器。检查是几何检查及受限场景的排版估算；组合、图表、旋转对象只检查外框，报告明确记录限制，不宣称代替 Office 的实际排版。

### 字体与原生列表

默认文字为微软雅黑、黑色 `#000000`，正文和各浅色主题保持黑色；标题、关键词及状态允许显式颜色、粗体等强调。显式选择 `graphite` 时使用浅色对比文字。

列表保持既有 `level/text` 输入，支持 1–4 级，使用 DrawingML 的 `a:buChar`、`a:buAutoNum` 和段落悬挂缩进，符号不拼入正文。富文本、条目内软换行、HTML 预览、字号适配及高度估算同步支持。不能安全提取的源原生列表保留在母版中并明确报告。

### 母版区域

新增命令：

```text
python .agents/skills/native-ppt/scripts/ppt_tool.py inspect-master master.pptx
python .agents/skills/native-ppt/scripts/ppt_tool.py render deck.json --out output/deck --strict-layout
```

配置顶层和逐页支持 `masterRegions`，例如 `{"detect":true,"titleHeight":96,"footerHeight":32}`；逐页覆盖全局，显式高度覆盖读取结果。区域高度以 JSON 页面的像素计，母版尺寸不同会自动换算读取值。源样例页实际存在的标题/页脚占位符参与保留区计算；版式或母版中未实例化的占位符仅作为候选返回。

元素的 `region` 支持 `body/title/footer/full`，正文检查 `titleHeight <= y` 且不侵入底部页脚区。内置标题、脚注及封面组件可自动识别；第三方组件可显式声明。`full` 仅跳过保留区检查，仍检查页面边界和内容溢出。

### 元素库与说明

新增洞察卡、价值卡、决策卡、里程碑横条、风险卡、行动卡、摘要横幅、前后对比横条、能力卡和结论面板，共 10 个组件；内置库合计 59 个。新增 `examples/modern-elements.json` 的 5 页整页编排，全部示例合计 7 份、67 页。已同步样例输入、Schema、库格式、提取说明和 SKILL，并重新生成 `assets/demo/library-demo.html`，无跳页。

- 原生列表 XML 验证项目符号、自动编号、多级缩进、软换行、黑色正文与局部强调；确认正文未拼接项目符号。
- 母版高度读取、全局/逐页覆盖、关闭推断、尺寸缩放、保留区侵入与严格失败均符合预期。
