# UML Studio 绝对定位与布局性能

## 实施方案（2026-11-28）

以 `.agents/skills/uml-studio/src` 为唯一事实来源。

### 现状诊断

- 工作台每次只渲染当前图。单张节点图（8–15 个节点）渲染即需 0.4–3.7 s（Node 端 `dist/core.mjs` 逐张实测）；带位置调整再翻倍，导致拖动、改字、切主题都明显卡顿。
- CPU 剖析：ELK 仅约 4%；`routeEdges / obstacleRouter`（约 48%）与 `placeLabels / segmentRectDistance`（约 38%）是热点。
- 有位置调整时 `renderGraphWithSpacing` 先完整跑一遍基线（路由 + 标签 + 可能的拥挤/标签重排递归），再应用调整重跑路由和标签，因此拖动一次 ≈ 两次完整渲染。
- 位置以相对自动布局的 `dx/dy` 存储，自动布局一变（改文字、加节点）元素就跟着漂移；`x/y` 为左上角固定。
- 拖动预览期间 SVG 尺寸不变，元素拖出边界即被裁切，释放并重算后才可见。

### 数据契约（新）

```json
{ "layout": { "adjustments": { "elements": { "nodes/review": { "cx": 320, "cy": 180 } } } } }
```

- `{cx, cy}`：元素**中心点绝对坐标**（图内逻辑坐标，即 `[data-layout-root]` 内坐标系），元素被固定（pinned）。
- 旧格式 `{dx, dy}`（相对偏移）与 `{x, y}`（左上角固定）继续可读，编辑器一旦拖动即改写为 `{cx, cy}`。
- 渲染出的可调整元素在原 `data-adjustment-key / data-layout-x / data-layout-y` 基础上增加 `data-layout-cx / data-layout-cy`（当前渲染中心）以及固定时的 `data-pinned="true"`。

### 布局：部分固定的自动布局

- 结构缓存：以“去掉 `layout.adjustments` 的 spec + 主题”为键缓存基线结果（ELK 结果、拥挤/标签重排后确定的间距与基线标签判定），拖动只做“应用固定 → 避让 → 路由 → 标签”一次。
- 固定元素严格放在 `cx/cy`；未固定节点保持自动布局位置，若与固定元素（含间距）重叠，沿流程方向推开到最近空位；容器按成员扩展（成员全部固定时贴合成员）。
- 无调整的图输出必须与改动前逐字节一致。

### 性能

- 在不改变输出的前提下优化 `obstacleRouter`、`routeEdges`、`placeLabels`、`segmentRectDistance` 等热点（空间索引 / 预计算 / 剪枝 / 优先队列等），以 `temp/uml-baseline` 快照逐字节对比。

### 画布交互

- 拖动结束提交中心点绝对坐标 `{cx, cy}`（替换原 `dx/dy` 累加）。
- 新增元素 / 粘贴：先把现有节点冻结为当前渲染中心（仅节点图类），新元素放到不与任何元素重叠、且与现有内容保持间距的空位（内容外侧，必要时扩大画布）；粘贴多个保持相对位置。
- 拖动预览时实时扩展 SVG 视窗与背景，元素始终可见。
- 消除一次提交触发的重复渲染等前端冗余。

### 分工

1. 子代理 A（性能）：`graph.ts` 路由与标签热点函数，输出逐字节不变。
2. 子代理 B（布局契约）：`types.ts / schema.ts / validate.ts / special.ts`、`graph.ts` 中的 `applyManualElements / adjustmentDelta / renderGraphWithSpacing` 与缓存。
3. 子代理 C（画布）：`DiagramCanvas.vue / Studio.vue / svg.ts`。
4. 测试子代理：类型检查、构建、已有测试、浏览器烟测。

## 实施结果

### 性能

| 场景 | 改动前 | 改动后 |
|---|---|---|
| gallery 64 张图全量渲染（Node） | ≈ 31.8–33.8 s | ≈ 5.8–6.0 s |
| 单图切换颜色类主题（如 commerce-physical） | ≈ 2.8–3.1 s | 首次 0.8 s，之后 1–2 ms |
| 浏览器内切主题 | — | ≈ 45–93 ms（缓存命中） |
| 拖动后重渲染（24 张节点图合计） | ≈ 6.2 s | ≈ 2.0 s |

- 路由 `obstacleRouter`：按行/列预筛障碍与线段、网格边代价惰性缓存、平行数组二叉堆、复用 TypedArray 缓冲区；`routeEdges` 以下界剪枝 16 种端口组合。
- 标签 `placeLabels`：候选数字化，按（分数下界, 原顺序）堆式取优；`segmentRectDistance` 用包围盒下界跳过 `hypot`。
- 无调整图输出与改动前逐字节一致（64 张快照 + 496 个变体验证）。
- 基线缓存（模块级 LRU 16）：键为“去掉 `layout.adjustments` 的 spec + 几何相关主题字段（`fontSize / nodeWidth / nodeHeight / gap`）”，颜色、调色板、字体族、圆角、线宽不入键，因此切换颜色主题直接复用几何。命中有调整的渲染只做“固定 → 避让 → 路由 → 标签”一次。
- 工作台每次只渲染当前图；`applySpec` 只校验当前图，`json()` 按对象缓存，去掉画布重复 `validateSpec` 与无监听的克隆，一次拖动 JSON 序列化量约降为 1/6。

### 位置契约

- 推荐 `{cx, cy}`：元素视觉中心绝对逻辑坐标并固定。中心定义：节点 / 分组 / 泳道 / 连线标签为矩形中心（节点不含外置说明文字）；时序参与者为头部框中心，消息为线中点，备注 / 分隔线 / 片段为框中心；鱼头、鱼骨分类为框中心，原因为文字行中心。
- 旧 `{dx, dy}`、`{x, y}` 仍可读；节点图的 `x/y` 同样视为固定。
- 有任一调整时 SVG 输出 `data-layout-cx / data-layout-cy` 与 `data-pinned="true"`；无调整的图不输出（保持逐字节一致），画布以 `data-layout-x/y` + 几何兜底。
- 泳道固定只作用于横跨流程方向，沿流程方向分量忽略。

### 部分固定自动布局

1. 容器由外到内放置并带动未固定成员，固定节点放到设定中心。
2. 容器由内到外贴合：固定容器以设定中心对称扩展；成员全部固定的容器贴合成员；其余只扩不缩。
3. 未固定元素距固定障碍不足 12 时，被推开到让出完整 `elementGap`；推动单位为不含障碍的最外层未固定分组，方向取位移最小者（同值优先流程方向），可连锁。
4. 泳道正反扫描去重叠，并沿流程方向统一长度。
5. 固定元素互相重叠不做处理；画布在松手时把节点沿拖动方向推离其它固定节点，渲染失败直接恢复上一张 SVG 并提示。

### 画布交互

- 拖动提交 `{cx, cy}`；分组 / 泳道拖动同步改写已固定的成员。时序 / 鱼骨首次拖动先写精确 `dx/dy`，渲染后转换为 `{cx, cy}`（只改数据不重渲染）。
- 添加元素 / 粘贴（节点图）：先冻结现有节点（中心为估算值时先存精确左上角 `x/y`，渲染后转换为 `cx/cy`），有成员的分组取消固定以贴合成员；新元素放在内容包围盒外侧（TB 右侧、LR 下方，间距 64，靠近视口中心），容器内新增在容器附近找扩张最小的空位；泳道图按选中项或空位所在泳道自动指定 `lane` 并放在泳道带内。一次新增只渲染一次。
- 拖动时按被拖元素、跟随标签与连线预览实时扩展 svg `viewBox / width / height`、背景 rect 与画板；向左 / 上扩展以滚动或 CSS 平移补偿，Esc 复原。已知限制：画板小于视口居中时，重新居中会产生半个增量的位移。

### 验证

`vue-tsc`、`npm run build`、`npm run demo:verify`（27 PASS）通过；`npm test` 101 项中 3 项为改动前既有失败（分支主干、raster marker 计数、复杂时序箭头计数，均因 `-sec / -start` marker 变体未更新测试）；`test:editor` 脚本等待已不存在的“编辑图表”按钮，属既有过期。
