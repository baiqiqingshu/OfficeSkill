# UML Studio 模板与技能目录整理

日期：2026-10-28。

## 目标与范围

依据现有 `SKILL.md`、根目录 README、impeccable 和 frontend-design 的操作型界面原则，改善离线绘图工作台的操作层级。保留 Vue / TypeScript / SVG / ELK 架构、海蓝主题、全部图类型、多图数据、自动布局和离线导出能力。

用户优先快速获得可用原型，不新增测试代码；实施由子代理并行完成，验证另交独立子代理。完成后更新使用文档并自动提交本次变更。

## 实施分工

| 工作 | 实施边界 | 完成标准 |
| --- | --- | --- |
| 界面整理 | Studio 与编辑器布局、交互文案、样式 | 画布优先，编辑和进阶设置按需展开，常用动作易于定位；支持窄屏和键盘 |
| 鱼头样式 | 查证来源与专用鱼骨渲染 | 如实标明来源，保留递归原因、结果文字和 SVG / 位图导出 |
| UCD 文件精简 | 先区分源码、示例、历史和缓存 | 保留当前未提交成果，不降低生成效果，技能目录实际文件数小于 100 |
| UML 文件精简 | 待并发修改完成后实施 | 不删除功能、图类型或示例内容，构建后仍小于 100；同步所有路径引用 |
| 独立验证 | 完成实施后构建和人工交互检查 | 不新增测试代码，记录实际执行结果与限制 |

## 并发与数据保全

开始时 uml-studio 无未提交文件，ucd-studio 已有一批其它工作的未提交修改。不能回退或覆盖这些成果；精简应在其当前内容上进行。用户提示另一个 Codex 正修改 uml-studio，因此文件结构整理须等待该工作结束，期间仅开展互不重叠的探索与定向修改。

文件数量同时记录 Git 管理文件和目录内实际文件，缓存和历史不能混为源码。历史若归档，先验证归档可完整恢复；不以删除示例和压缩掉可编辑源码来达成数量目标。

## 验证与交付

按变化执行已有构建、类型检查、生成命令和必要现有检查；实际浏览桌面和窄屏布局，核对编辑、应用、切换图形、样式与导出入口。生成最新离线 Demo，使交付可直接打开审阅。验证记录及精简前后文件数随完成结果更新。

## 实施结果

界面、九种鱼头及目录精简均由子代理完成，独立验证由另一子代理承担，没有新增项目测试代码。UCD 历史无损归档后实际从 230 降至 81 个文件；UML 通过归并声明、组件样式和外置缓存从 130 降至 99 个文件，全部 40 份示例及路径保持。

并发原任务已提交为 `6d231ea`，本轮基于其完整成果继续整理。鱼头真实来源为本机 FishboneStudio，未在 UCD 中发现对应素材；来源及 MIT 许可已随离线产物保留。主代理已查看桌面、手机和长文字鱼头拼图，最终检查的命令、覆盖范围和结论见 [独立验证记录](validation.md)。

按用户后续反馈，鱼骨图默认恢复为修改前的原版鱼头、比例、文字位置和主骨连接；未设置 `headStyle` 或显式设置 `classic` 都使用原版。扩展造型保留为显式选择，不改变默认效果。新增 `white` / “纯白”图表主题，使用白色背景及节点、深色文字、蓝色线条，供全部图型和 CLI 选择。
